# GTA 6 Guide – working notes for Claude

Fan-made GTA 6 guide and 100% tracker. Static site generated by `node build.mjs` into `dist/`.
Live at **https://trackgta6.com** (Cloudflare Workers: `wrangler.jsonc`, `worker.js`). www.trackgta6.com forwards there.
gta6-guide.darpanarora82.workers.dev still works as a backup. Vercel is no longer used.
The editor is https://trackgta6.com/edit. Every push to `main` deploys.

## Rules the owner has set

- **Tracker item batches go straight to `main`** (no pull request). They are live in about a minute.
- **Code or design changes go through a pull request** with the Cloudflare preview link; merge only when the owner says "merge".
- **Spoilers:** mark `"spoiler": true` on anything that names a mission, a story event or a character twist. Collectibles and general activities are not spoilers unless their note gives the story away.
- Write every name and note in our own words. Never copy text from other guide sites.
- Commit messages end with the attribution lines from the session's system reminder.

## Before editing anything

The owner publishes items from `/edit`, which commits to `main` directly. **Always pull the latest `main`
(especially `data.json` and `src/assets/img/items/`) before changing files**, or you will overwrite published items.

## Adding tracker items from the owner's screenshots

The owner plays on PS5, sends screenshots with a few words each, and Claude turns them into items.

1. Work out the category (`missables`, `collectibles`, `activities`, `trophies`) and region
   (`Vice City`, `Leonida Keys`, `Grassrivers`, `Port Gellhorn`, `Ambrosia`, `Mount Kalaga`, or none).
2. Give each item the next free ID in its category: `<category>-NNN` (e.g. `collectibles-014`).
   **Never change or reuse an ID once published** – visitors' ticks are stored against it.
3. Photos: save a 1280px-wide JPEG (quality ~80) as `src/assets/img/items/<id>.jpg` and a 480px-wide
   thumbnail as `src/assets/img/items/<id>-t.jpg`.
4. Append the item to the right category in `data.json`:

   ```json
   {
     "id": "collectibles-014",
     "name": "#14 – under the north pier",
     "region": "Leonida Keys",
     "note": "Swim under the north end of the pier; it's on the second pillar.",
     "img": "/assets/img/items/collectibles-014.jpg",
     "thumb": "/assets/img/items/collectibles-014-t.jpg",
     "added": "2026-11-19",
     "missable": true,
     "spoiler": true
   }
   ```

   Only include `missable` / `spoiler` when true. `added` (YYYY-MM-DD) shows a "New" badge for 36 hours.
   Set the top-level `"updated"` to today's date.
5. Run `node build.mjs` to check it builds, commit to `main`, push, and reply with the list of IDs that went live.

## The owner's own editor

`/edit` also has **Quick add with AI**: the owner picks several screenshots, adds a hint (typed or spoken),
and `POST /edit/draft` asks Workers AI (`@cf/meta/llama-3.2-11b-vision-instruct`, free daily allowance) to
draft each item. The owner reviews the drafts and presses **Publish all**.


`/edit` (password: Cloudflare secret `EDIT_PASSWORD`) lets the owner add drafts with a screenshot and press
**Publish drafts**. `worker.js` uploads photos and commits items to GitHub in one commit, using the Cloudflare
secret `GITHUB_TOKEN` (fine-grained, Contents read/write on this repo only). If an ID is already taken, the
Worker renumbers it.

## Where things live

- `content/*.json` – site text (characters, places, FAQ, editions, launch, videos, radio, features)
- `data.json` – tracker categories, regions and items
- `src/tracker.html` – tracker engine (its script is reused inside the site layout by `build.mjs`)
- `src/assets/site.css` – all styles (inlined into every page at build time)
- `src/assets/region.js` – visitor country detection from time zone (generated from `src/js/region.src.js`)
- `IMAGES.md` – how character and place photos are named
